# w7s — o utilitário do gecko-engine (lado Speculum)

O **contrato da ferramenta** vive no repo dela: `Tools/npm/w7s/docs/01-concepts.md` …
`10-ci.md`. Este documento é o lado Speculum: por que existe, a dívida do modelo antigo, e
onde cada coisa de hoje vai parar.

Regra que vale aqui como em todo o projeto: **evidência, não memória.**

---

## 1. O que motivou

O caminho de aplicação antigo **não reproduzia o binário que estava rodando**, e isso foi
medido, não suposto. Inventário do checkout da WSL em 2026-09-18 (backup bruto no commit
`9731c11c`, `gecko-engine/.rescue/20260918-033259Z`, 744K):

- **26 arquivos modificados + 19 novos = 45.**
- **Cinco arquivos do upstream** estavam no espelho e **fora** do `copy-hash`:
  `docshell/base/BrowsingContext.{cpp,h}`, `CanonicalBrowsingContext.cpp`,
  `dom/base/Document.{cpp,h}`. `BrowsingContext.cpp` é onde vive o
  `SpeculumMintNestedIfProjected` — lei da spec. Um checkout limpo produzia um Firefox sem
  isso.
- **Classe C:** `speculum/{app.mozbuild,confvars.sh,moz.configure}` — a configuração de
  aplicação do fork nunca esteve no repo, porque o `mirror-gecko-patches.sh` filtrava
  `^speculum/` de propósito.
- **CRLF contaminando a árvore:** `ContentChild.cpp` (10373 linhas alteradas) e
  `PContent.ipdl` (4044) reescritos inteiros pelo `cp -f`, com `+`/`-` equilibrados.
- **Commits locais** no checkout (`head 9aaffa3b` ≠ `base feec67e6`), num git sem remote.

Mais: três representações concorrentes do mesmo delta (cópia integral, hunk, reescritor
python com idempotência por `grep -q`), 13 arquivos do upstream guardados como cópia
integral, `cp -f` incondicional em 32 arquivos antes de todo `mach` — regenerando IPDL,
re-rodando o build backend e forçando relink do libxul a cada build — duas listas de arquivo
que podiam divergir, caminhos absolutos dentro de script, e 3,2 GB de artefato gerado em
`gecko-engine/gecko-dist/` com symlink pendurado apontando pra um objdir que só existia na
WSL.

## 2. O modelo novo, em três caixas

```
┌─ 1 ─ repo (Windows) ────────────────┐   nossa fonte, versionada
│  gecko-engine/                      │   w7s.json · modifications/ · tests/
└──────────────┬──────────────────────┘
               │ w7s gecko make …
┌─ 2 ─ container do toolchain ────────┐   a imagem do w7s, versionada com ele
│  /gecko-pristine  (read-only)       │   o Firefox ESR pinado vem NA IMAGEM
│  volumes: gecko-source, gecko-binary│   descartáveis, reconstruíveis
└──────────────┬──────────────────────┘
               │
┌─ 3 ─ repo (Windows) ────────────────┐   o entregável
│  gecko-engine/dist/<alvo>/          │   firefox.tar.gz + build.json
└─────────────────────────────────────┘   → dockup constrói a imagem de produto
```

Duas frases que explicam o resto:

> **A versão do Firefox é propriedade da release do w7s, não do nosso repo.** Não existe pin
> pra declarar, commit pra verificar, clone que fique velho, nem possibilidade de duas
> máquinas terem árvores diferentes. Trocar de ESR é trocar de versão do w7s.

> **O toolchain existe porque o alvo é Linux.** Cross-compile Windows→Linux não está na
> matriz testada da Mozilla, então seria sysroot e toolchain artesanais mantidos por nós. O
> container roda na *nossa* máquina; só o userland é Linux, porque a saída é Linux.

Contraste que vale registrar: `dotnet publish -r linux-x64` **funciona** do Windows, e é
assim que o `host/` é publicado pela imagem de produto. Funciona porque .NET é gerenciado e
a Microsoft distribui o runtime pack do alvo. Gecko são ~30 milhões de linhas de C++ que
precisam dos headers e das libs do alvo. Categorias diferentes.

## 3. Como as modificações são declaradas

Um mecanismo só: **escrever o arquivo inteiro no caminho de destino.** Sem hunk, sem âncora.
Mexer num arquivo do Firefox significa segurar o arquivo todo — custa uma cópia e compra
duas coisas: quem lê o repo vê o código real em contexto, e a subida de ESR produz um merge
de três vias legível em vez de âncora quebrada.

Quatro entradas cobrem os 45 arquivos:

| entrada | conteúdo | `replacesGeckoSource` |
|---|---|---|
| projection runtime | nosso C++ (`dom/base/Speculum*`, `dom/ipc/Speculum*`) | `false` |
| runtime install points | os arquivos do Firefox que chamam o runtime | `true` |
| fork build configuration | `speculum/{app.mozbuild,confvars.sh,moz.configure}` | `false` |
| producer headers | `producer/include/speculum/*.h` → `third_party/` | `false` |

`replacesGeckoSource` é verificado nos dois sentidos, arquivo por arquivo, contra
`/gecko-pristine`. Declarar errado é erro; declarar errado em silêncio é impossível.

Árvore resultante:

```
gecko-engine/
  w7s.json
  modifications/
    runtime/               dom/base/Speculum*.{h,cpp} · dom/ipc/Speculum*.{h,cpp}
    install/               docshell/base/BrowsingContext.cpp · dom/base/Document.cpp
                           dom/ipc/PContent.ipdl · ipc/ipdl/sync-messages.ini · …
    build-configuration/   speculum/{app.mozbuild,confvars.sh,moz.configure}
  producer/include/speculum/*.h
  host/                    orchestrator + supervisor + abi (.NET)
  image/Dockerfile         imagem de produto (dockup constrói)
  tests/
  lab/                     scripts de diagnóstico
  dist/<alvo>/             gerado · gitignorado · visível
```

## 5. Passo zero — a dívida, uma vez

O backup bruto já está no git (`9731c11c`). Falta converter os 45 arquivos em
`modifications/`, e isso **não é fase do desenho novo**: no desenho novo ninguém edita dentro
da oficina, então a situação não se repete.

Ainda por rodar no checkout antigo, antes de destruí-lo:

```bash
GECKO=/root/speculum-gecko/checkout
BASE=feec67e62a5148b41fd017ccbbc463e8a6f9e83d
R="…/gecko-engine/.rescue/20260918-033259Z"

cat "$R/log.txt"                          # o que foi commitado no checkout
git -C "$GECKO" diff --stat -w "$BASE"    # o delta REAL, sem o dano de CRLF
for f in dom/ipc/ContentChild.cpp dom/ipc/PContent.ipdl; do
  printf '%-32s CR=%s\n' "$f" "$(grep -c $'\r' "$GECKO/$f" || echo 0)"
done
```

O segundo comando é o que importa: se `ContentChild.cpp` e `PContent.ipdl` caírem de 10373 e
4044 linhas para algumas dezenas, o delta real é pequeno e a conversão é tranquila.

**Critério de aceite:** com os 45 arquivos em `modifications/`,
`w7s gecko make gecko-source --dry-run` contra o checkout atual reporta **zero escritas**.
Reportou escrita, a conversão perdeu alguma coisa.

## 6. Decisões

| # | decisão |
|---|---|
| 1 | **W7S = Websete Speculum.** Pacote independente (`@rodrigopjax/w7s`, repo `rpjax/npm-w7s`, em `Tools/npm/w7s`), tailored ao Speculum. Convenções copiadas do `@rodrigopjax/dockup`. |
| 2 | **Uma imagem**, publicada pelo w7s e versionada com ele, carregando o Firefox pinado em `/gecko-pristine` e o toolchain. Compilar, testar e rodar acontecem em container dela. |
| 3 | **Um mecanismo de instalação:** escrever o arquivo inteiro. Sem hunk, sem âncora. |
| 4 | **Duas chaves no manifesto:** `modifications` e `tests`. Sem schema, kind, id, source, environments ou stateDir. |
| 5 | **Nada implícito.** Sem default derivado, sem convenção de nome de pasta, sem fallback silencioso; chave desconhecida é erro. |
| 6 | **dockup constrói todas as imagens de produto**; o w7s só produz `sidecar-package` e o expõe como provider. |
| 7 | **Teste de release-gate não pode mutar o próprio ambiente** — sem pacote extra, sem rede, runner só da lista da imagem. Validado no manifesto. |
| 8 | Renomes: `speculum-wire/`→`producer/`, `supervisor/`→`host/`, `patches/`→`modifications/`, `devpath/`→`lab/`. |

### Pendentes

1. Converter os 45 arquivos (passo zero acima).
2. **Fork como verdade.** `rpjax/firefox` / `speculum/153.2.0esr` existe no `UPSTREAM` antigo
   e não é lido por nada. Com a árvore pristina vindo da imagem, promover o delta a commits
   passou a ser decisão do **w7s**, não do Speculum. Fica pós-V1.
3. **Windows como alvo.** É porte, não flag: o `host/` assume Linux (o processo de conteúdo
   roda em chroot) e o toolchain seria MSVC.
4. **Limpeza do `lab/`** — 121 scripts e 124 capturas versionadas. Trabalho próprio.

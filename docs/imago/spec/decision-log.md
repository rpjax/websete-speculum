# Imago decision log

Append-only. Never rewrite a row; supersede it with a new one and mark the old `superseded by D-0xx`.

| id | date | decision | rationale |
|---|---|---|---|
| **D-001** | 2026-09-03 | Subproject named **Imago**. Folder `docs/imago/spec/`. | Latin *image / likeness / reflection* — fits the Speculum lexicon, unused in current vocabulary, short enough for type prefixes. Alternatives considered: Simulacrum, Calque, Vestige. |
| **D-002** | 2026-09-03 | Output is **generated**, never seeded. Nobody hand-edits emitter output; the site changes → recapture and regenerate. | Componentization is a maintenance abstraction that only pays if humans edit the artifact. Under "generated" it is pure cost, and worse, it is what makes regeneration destructive. Consequence: byte-idempotence becomes an accept criterion (O5), not an aspiration. |
| **D-003** | 2026-09-03 | Bundle and observation data are **separate artifacts** (I1). Response bytes never become markup; they enter only as fixtures through a dev adapter. | Mixing produces a snapshot that lies about being an application: it looks alive, serves stale data, and cannot be regenerated. Separation is also what makes the contract independently useful. |
| **D-004** | 2026-09-03 | **Flat by default** (I4). No semantic componentization. Exactly two mechanical layers: repeated **fragment** and data **slot**. | Component boundaries are only derivable where there is repetition (≥2 instances); with one instance you bake data into structure. Flat output with marked slots can be componentized later without recapture; the reverse is not true. |
| **D-005** | 2026-09-03 | "100% functional and identical" and "our own maintainable code" are **two emitters over one IR** (`rehost`, `flat`), not one output. | Extraction yields structure and style. Behaviour comes from the origin's JS, from source maps, or from someone writing it — there is no fourth source. One artifact cannot be both; two emitters over one IR cost almost nothing extra and are honest. |
| **D-006** | 2026-09-03 | **Atom identity is declared** by the exploration script (A-1); the harness may only propose (A-2). | Automatic state identity is undecidable in general. Declaring it keeps discovery useful without letting inference become the source of truth, and avoids an open-ended heuristics rabbit hole. |
| **D-007** | 2026-09-03 | The **IR is the only emitter input** (IR-6). Capture never emits; emitters never touch the network. | This seam is what lets a future emitter (including a source-map port, OPEN-1) exist without recapture, and what keeps the two artifacts from contaminating each other. |
| **D-008** | 2026-09-03 | Imago is **not a MirrorMode** and shares no PageProjection protocol code (I7). Only the `attachShadow` patch is reused. | Coupling capture to the live projection path would put a schedule workaround on a product hot path. Reusing the shadow patch is a bounded, already-paid cost. |
| **D-009** | 2026-09-03 | Anti-bot is **explicitly out of scope**. Challenge widgets are stubbed (E-6) and Imago may never be cited as progress on the anti-bot requirement. | A challenge is a live conversation with a third-party origin; it cannot be replayed from a bundle. Conflating the two would hide the real anti-bot work behind a green demo. |
| **D-010** | 2026-09-03 | **Supersedes D-006.** No exploration script. Capture is a continuous **timeline** written while a human browses freely; **atoms are a curation layer** over it, named live (Mark) or afterwards in the panel. The recorder proposes; a human decides. | The flow is manual browsing, so nothing can be declared up front. What D-006 actually protected — a human, never a heuristic, decides state identity — survives intact; only the mechanism changed. |
| **D-011** | 2026-09-03 | **Supersedes D-008.** Imago is a **standalone project beside the sidecar**, disconnected from all of Speculum: own browser launch, own injected agent (including its own `attachShadow` patch), own storage, own panel, own CI. Nothing imported in either direction. | Coupling a schedule tool to a product under active repair buys nothing and costs a permanent dependency in both directions. Techniques may be re-implemented; modules may not be shared. Duplication is the deliberate price of independence. |
| **D-012** | 2026-09-03 | **Revises D-009.** Challenges are **ignored, not solved**: captured and classified like any other traffic, then handled at **generation** time by per-host disposition (default `stub`). Anything added on top of a captured site — challenge handling, auth shim, mock layer, instrumentation — is a configured generation step. | Keeps capture dumb and honest while leaving a named seam where a future mechanism attaches. Imago still never counts as progress on the anti-bot requirement. |
| **D-013** | 2026-09-03 | **O5 splits.** O5a (generation idempotence: same session + same profile → same bytes) is **required**. O5b (capture reproducibility) is **dropped**: a human-driven session cannot be replayed. Its purpose is served by within-session conflict reporting (A-8), resolved by a human in the panel. | A property the design cannot have must not sit in the accept table as a permanent failure. Divergence between two visits is expected under manual browsing, so it becomes curation, not error. |
| **D-014** | 2026-09-03 | A **closed session is immutable** (S-1) and generation never writes into it (S-2). All human curation lives in a separate `overlay.json`; a generation run is its own entity keyed on `(sessionId, profileHash)`. | Capture is expensive and unrepeatable; generation is cheap and repeatable. Freezing the expensive half is what makes reconfiguring and regenerating N times safe. |
| **D-015** | 2026-09-03 | Oracles run **offline against references stored during the session** (reference screenshots, matching-rule sets, geometry — A-9), never against the live origin. | The origin drifts and the session is browsed once. Comparing against a moved target would make every oracle run an argument instead of a measurement. |
| **D-016** | 2026-09-03 | **Preview is a third panel feature, served by the Imago Node app itself** — the operator never starts a web server. `file://` is rejected as the mechanism. | "No web server" means no step for the operator, not no HTTP: from the filesystem, `fetch`, ES modules, root-absolute paths and history routing all break, so a `file://` bundle is not the bundle. The app is already a server; it absorbs the job. |
| **D-017** | 2026-09-03 | Each previewed run is served on **its own ephemeral loopback origin, root-mounted** — never the panel's origin, never a subpath. | Root mounting is required because bundles reference `/assets/…`, and rewriting the artifact to view it means no longer viewing the artifact. Isolation is required because a bundle carries third-party JS captured from a site we do not control, and the panel can read the filesystem and launch browsers. |
| **D-018** | 2026-09-03 | Preview API modes: **`off`** (default), **`fixtures`**, **`proxy`**. | `off` exposes the real empty/error states nobody captured; `fixtures` gives the live-looking form used for O1; `proxy` points the bundle at the backend under construction, turning preview into that team's harness — the front-end drives the half-built server and mismatches surface as behaviour instead of prose. |
| **D-019** | 2026-09-03 | Preview is **default-deny egress** and is **where O4 runs**; the classified request tape is the oracle's evidence. | Every request already passes through the app, so network closure needs no second harness. Silent allow is how a demo bundle quietly phones an analytics vendor. |
| **D-020** | 2026-09-03 | Preview is **read-only**: it never writes to a run (S-2) or a session (S-1). | A wrong output is fixed by changing the profile and regenerating. Editing in the viewer would make generated output unexplainable and kill I2 on the first fix. |
| **D-021** | 2026-09-03 | **Closes OPEN-9.** Imago lives at `imago/` in the repo root, with its own `package.json`, build and CI job, and its own `scripts/check-boundaries.mjs` that fails on any import crossing in or out. | Real independence (I7) at low friction: one clone, spec beside code, and promoting it to its own repo later is a `git filter-repo`. The boundary check is what makes I7 enforced rather than remembered. |
| **D-022** | 2026-09-03 | **Closes OPEN-6.** Panel = Node + TypeScript (Fastify) serving its own React/Vite front end, with a WebSocket for the live tape. **Nothing imported from `web/`.** | The panel needs push (snapshots appearing, request tape) and thumbnails from day one, and curation (F3) plus side-by-side comparison (F5) would strangle a server-rendered page. Same conventions the team knows, zero coupling. |
| **D-023** | 2026-09-03 | Browser driver = **`playwright-core`**, `launchPersistentContext` headed with Imago's own profile dir, `channel: 'chrome'` by default (no browser download), `executablePath` overridable. Agent installed via `addInitScript`. **Not patchright, no stealth stack.** | Challenges are ignored (D-012), so stealth buys nothing and costs a permanent dependency. `playwright-core` + system Chrome keeps install light. If one target's *capture* is ever blocked, that is a per-target config switch, not an architecture change. |
| **D-024** | 2026-09-03 | **The panel is the only interface.** No CLI, no console entry point — not even as a stepping stone. `npm start` opens the GUI; everything else (`test`, `build`) is tooling, not product surface. | A console path is a second interface to keep working, and it quietly becomes the one that is maintained while the GUI rots. The first pass at F1 shipped a CLI "to get moving" and had to be deleted; recorded so nobody re-adds one for the same reason. |
| **D-025** | 2026-09-03 | **Windows only.** One desktop platform: Windows paths, Windows Chrome, `cmd /c start` to open the panel. No cross-platform abstraction layer, no POSIX branch, no "it should also work on…". | The tool runs on one machine, the operator's. Portability that nobody exercises is untested code that constrains every design choice it touches. |
| **D-026** | 2026-09-03 | **A-11/A-12/A-13 + S-8/S-9/S-10** — in-flight is tracked by request age (fresh blocks settle, long-lived does not), a never-settling page gets flagged `interval` snapshots, the stall reason is published; the browser dying is a recoverable state, orphaned sessions are finalized at startup, and the panel shows when it is offline. | First real browse (eneba, 49 requests, 4.2 MB) produced **zero snapshots**: ten requests permanently in flight held the settle predicate hostage. Chrome then crashed, an unhandled rejection in the poll loop killed the app, and the panel sat frozen on "recording" with no way to close. Three failures, one root cause each — a predicate that assumed a quiet network, a loop that could throw, and a UI that assumed the process behind it was alive. The settle decision is now a pure function with asserts (`src/recorder/settle.ts`), so the fix is provable rather than hopeful. |
| **D-027** | 2026-09-03 | **S-11** — panel actions carry no payload, the server tolerates an empty JSON body, and errors surface as sentences (`{ ok:false, error }` or a framework envelope unwrapped), never as raw status text. Asserted over real HTTP in `npm test`. | **Mark state** and **Close sandbox** sent `content-type: application/json` with no body; Fastify's parser rejected both with `Bad Request`, so a live session could not be closed — a header made the sandbox unclosable. The class of bug (a contract mismatch between panel and server that no unit test could see) is why the smoke now boots the real server and calls the real endpoints. |
| **D-028** | 2026-09-03 | **C-4a/C-4b + the resolver actually resolves.** A subresource is a byte the page needs, decided by a pure ref policy (`src/shared/refPolicy.ts`) that never admits `a href`, `base`, `area`, or non-asset `link rel`; a non-2xx no longer counts as fetched; and at close the resolver **fetches** every reference the page never requested before reporting what is still missing, grouped by host with a reason. | The first eneba session reported **591 unresolved references** — including `apps.apple.com` and `discord.gg`, which are links, not assets. Two bugs stacked: collection swept up navigation targets, and the closure check accused instead of resolving. Both made C-4 useless in exactly the way that matters: it declared a good session broken, so nobody could trust it to declare a bad one broken either. |
| **D-029** | 2026-09-03 | **`rehost` v1 ships with a bundle service worker.** HTML and CSS are rewritten; JavaScript is not (E2 forbids blanket replacement in minified bundles). What the rewrite cannot reach, a generated worker resolves at runtime from the route map, and anything not in the map goes to the preview's API layer or is refused. | The URLs a minified React app builds at runtime cannot be rewritten safely, so a rewrite-only bundle silently leaves for the real origin — E2 would be a claim, not a property. Routing every request through a worker makes the closed world enforced from inside the bundle, and gives the preview one place to apply the `off`/`fixtures`/`proxy` decision. |
| **D-030** | 2026-09-03 | **Panel is the whole product surface, so it gets product treatment**: rail navigation with counts, keyboard shortcuts (`1/2/3`, `m` to mark, `/` to filter), toasts instead of inline error text, session filter with relative times and sizes, tape with filter/pause/count, remembered form state, copy-path and open-folder (Windows, and only inside `IMAGO_HOME`). | D-024 makes the GUI the only way in. A single-interface tool whose interface is inconvenient is an inconvenient tool — there is no CLI to fall back to, by design. |
| **D-031** | 2026-09-03 | **S-12** — artifacts carry a schema; the reader is strict; a session this build cannot read is listed apart with its reason and **deleted by the operator** through **Delete all unreadable**. No compatibility shims (repo law: none during V1), and **nothing is ever auto-deleted** — not at startup, not on mismatch. | The panel crashed on `undefined.slice`: sessions closed before the report gained host grouping had the old shape, and the reader assumed the newest one. First attempt was a translator (banned — a branch per historical shape, each a guess); second was purging at boot (wrong — the program does not get to throw away a browse a human produced). Refuse, name it, and give the operator the button. |
| **D-032** | 2026-09-03 | **S-13 + session management.** Delete (single, multi-select, and unreadable-in-bulk) with an irreversible-action confirm that states size and what is lost; delete a bundle without touching its session; rename through the **overlay**, never by rewriting `session.json` (S-1); disk size per session and in total; sort and filter. Plus a **How it works** view: every shortcut names the button it duplicates. | Management was missing outright — there was no way to remove a session, which on a tool that writes hundreds of MB per browse is not a gap but a defect. And the shortcut card listed keystrokes with no explanation of where they apply or what they do; under D-024 there is no CLI to discover behaviour from, so anything the keyboard can do the screen must show. |
| **D-033** | 2026-09-03 | **C-4c/C-4d** — the closing resolver sweeps every recorded textual body for absolute URLs and fetches them in rounds, fenced to hosts that already delivered a subresource in this session; long or over-long-segment paths are stored content-addressed instead of truncated. The bundle worker now reports **missing-asset** separately from **blocked**. | First real bundle rendered eneba's shell but not its content: the resolver only knew the URLs written in markup and CSS, so everything the app builds in JavaScript — and every image URL that arrives inside a GraphQL payload — was never downloaded and therefore never in the bundle. The instruction was explicit: download **all** assets. Truncating the image-proxy paths would have collided distinct assets onto one file, so long paths are hashed. And a missing asset was being logged as "blocked", which hid incompleteness inside a policy message. |
| **D-034** | 2026-09-03 | **F4.5 parity MVP applies to `rehost` before `flat`.** Entry-snapshot oracle references (screenshot + meta only) are captured at close; parity run (panel API) produces `parity/report.json` with O4/O4b/O1-lite. CSS rule parity (O2) and side-by-side viewer remain F5. Scripts may call the runner for CI smoke; the operator triggers parity from the panel (D-024). | Debugging eneba preview by hand (tape, ad hoc scripts) kept rediscovering the same gaps — missing GraphQL fixtures, missing imgproxy assets, empty hero slots. The spec already had oracles and references; they were unimplemented. Shipping a mechanical report first stops the circles; visual/CSS depth can follow without blocking `rehost` accept. |
| **D-035** | 2026-09-03 | **C-4e** — the closing resolver is extracted to `src/ir/resolver.ts` behind injected dependencies and proved in `npm test` against a simulated application (three live servers: origin, extension-less CDN, docs site that must not be crawled). Unknown hosts are promoted by **probe evidence** (one GET, content-type decides), promotions re-enter the proven set with earlier candidates intact, a fetched body's kind comes from its response, and the URL extractor handles IPv4/`localhost` while still refusing a bare `//`. | The sweep looked right and was wrong three times over, and each fault was invisible to inspection: a hardcoded `imgproxy` hostname (one target only), a promotion that was reported but never fed back (a discovered CDN yielded 1 asset out of 12), and every fetched body labelled `asset` (one probe of a docs page promoted it and the sweep began crawling it). Hand-testing on one real site could not find these — a simulated site with a known answer found all three in one run. |
| **D-036** | 2026-09-03 | **E-7/E-8/E-9** — the bundle worker routes by request intent (navigation/asset → bytes; anything else → the preview API layer, under the primary-host URL the recording knows); the preview's SPA fallback answers only navigations; the boot reload is guarded to once per tab. | The eneba bundle rendered perfectly and blanked about half a second later. Three causes stacked, all invisible in the tape: the app calls its GraphQL with a **relative path**, so under our origin the worker treated it as a local file and returned 404 instead of replaying the fixture; the SPA fallback answered extension-less data GETs with the entry HTML, killing the app on a JSON parse; and the boot script reloaded unguarded while the worker activated. Asserted over real HTTP: a same-origin POST API call replays from the session, an unknown data path 404s instead of returning HTML, and an unknown navigation still gets the shell. |
| **D-037** | 2026-09-03 | **C-4f** — the sweep separates **document hosts** (served HTML → asset-shaped URLs only) from **asset-only hosts** (never served HTML → everything, extension-less included); a page fetched by the sweep is stored but never mined for references; and the resolver carries a fetch budget (3 000) and a byte budget (400 MB). | Removing `looksLikeAsset` as a hard gate (D-035) fixed extension-less CDN assets and silently removed the anti-crawl guard: every link on the storefront's own host was fetched, mined, and its links queued — 8 800 URLs, hundreds of MB, minutes of failures. The earlier shape gate had been holding that back by accident, at the cost of the assets it wrongly rejected. Host kind is the real distinction, and it is decided by evidence like everything else. Asserted: the simulated site's own pages get **zero** hits while every extension-less CDN image is still downloaded. |
| **D-038** | 2026-09-03 | **E-10…E-13** — recorded hosts' complete origins are rewritten (HTML, CSS **and JS**) to `/__imago/h/<host>`, enumerated in the manifest; the preview resolves any unanswered data request through the same fixture/proxy layer; a GraphQL miss answers `{data:null,errors:[…]}` at 200; and the same operation with different variables answers, labelled. The boot script no longer reloads — the worker is an optimisation, superseding E-9. | The console named it: `Access to fetch at 'https://graphql.eneba.com/graphql/' … blocked by CORS policy`, then React #418/#423/#425. The API was never same-origin (D-036 fixed the wrong half): it is on its own host, built inside the JS bundle, so the app called the real internet and was refused before the request left the browser. With no data, hydration mismatched and React unmounted the nav, hero and first card row — "loads and then breaks". Three redundant paths now land in one resolver so the page works on first paint whether or not the worker took control. |
| **D-039** | 2026-09-04 | **E-14** — a file/directory path collision falls back to content-addressed storage instead of failing generation; the manifest records it. | Generating from a real session died with `EEXIST … mkdir '…/__imago/h/analytics.tiktok.com/api/v2/pixel'`: one URL had stored `pixel` as a file, another needed it as a directory. A site's URL space is not a filesystem's, so the collision is expected and the escape hatch already existed for long paths — it simply was not wired to this case. |
| **D-040** | 2026-09-04 | **E-15/E-16** — an extension-less URL takes its extension from the recorded content type (a document becomes `…/index.html`); the boot script is injected into every document, not only the entry. | Opening the preview made the browser **download** the page: the session's entry was `…/steam-gift-terraria-steam-gift-global`, an extension-less URL, so the file was served as `application/octet-stream`. Nothing was missing and nothing errored — the least legible failure the pipeline can produce. Fixing the extensions also dissolved most path collisions (E-14 remains for the rest), and exposed that only the entry document carried the worker's boot script. |
| **D-041** | 2026-09-04 | **E-17** — the protocol-relative origin form is no longer rewritten; hosts recorded as `telemetry`/`challenge` are answered with an empty `200` instead of a 404; and a missing asset is reported as `missing-asset` rather than routed through the fixture layer. | The bundle was byte-complete and still showed "We’re sorry — something went wrong". The console held all three causes. `GET https://__imago/h/nsure.eneba.com/core-config/config.json net::ERR_NAME_NOT_RESOLVED` was mine: the JS carried `//nsure.eneba.com/…`, I had replaced `//host` with a root-relative path, and the SDK concatenated `"https:"` onto it — a host that never existed. The 404s that followed (nsure, forter, sentry, mmapiws) then threw inside their own SDKs (`TypeError: Cannot read properties of undefined (reading 'url')`), and React’s error boundary replaced the page — a bundle destroyed by the analytics it does not need. And the webpack lazy chunks 404ing (`static.eneba.games/…part.js`) were being logged as API misses, which reads as a backend problem when it is a capture gap. Asserted over real HTTP: no `//host` rule is emitted, a recorded beacon host answers `200 {}` and lands on the tape as a stub, and a missing chunk answers 404 as an asset. |
| **D-042** | 2026-09-04 | **`flat` is written and becomes the default emitter** (E-18…E-27); `rehost` stays, unchanged, off the critical path. A run id now carries the profile hash, so two emitters cannot collide into one directory. The preview of a flat run answers an uncaptured path with 404 instead of the entry document. | Vinicius asked the question the whole session had been avoiding: instead of cloning the site's assets, why not **generate** them — read the DOM and the CSSOM and emit our own HTML and CSS. That is `flat`, which `emit.md` §3 had specified since day one and which was never written; D-034 chose `rehost` first and I spent the session polishing it. Every failure the eneba bundle produced — React #418/#423/#425, webpack chunks 404ing, an anti-fraud SDK throwing into the error boundary, CORS on the API host, five levels of fixture matching missing on a cache-buster — is a failure of **running someone else's application**, and none of them can occur in a page that runs nothing. The agent already collected everything `flat` needs (tree with shadow DOM, iframes, canvas and form state; authored sheets in cascade order with cross-origin refetched; the reference set), so the missing piece was the smallest in the pipeline. It also dissolves the sweep's reason to exist: the reference set is enumerated from the render tree, so it is finite and closed — no probe, no promotion, no budget, no crawl. Two faults surfaced in the writing, both from the same cause — a fixture shaped around one emitter proves nothing about the other: the run id had only second precision, so `flat` wrote into `rehost`'s directory; and the smoke's session carried `tree: 'x'` with no styles, which `rehost` never reads. | 
| **D-043** | 2026-09-04 | **E-28/E-29/E-30** — a frame's `src` is decided by the frame branch and dropped when we hold no document for it; stylesheet-relative URLs resolve against the sheet (`../assets/…`); one document per page rather than per snapshot, with the operator's last mark winning, and generation refusing to finish without an entry document. The `flat` bundle is now verified by **loading it in a real browser** and asserting zero 404s, zero requests off-origin and zero console errors. | The first flat bundle generated from a real session served `no such document in this bundle` at its own root. Three faults, one cause: **a fixture shaped around one case proves nothing about the others.** (1) The session had four snapshots of one URL and no marks; the document path was keyed by URL while decided per snapshot, so they overwrote each other and `index.html` was never written — the smoke used two distinct URLs, so it passed. (2) `iframe` was absent from the URL-attribute table, so six live external frames kept their `src` and the closed world leaked — the fixture had no cross-origin iframe. (3) The emitted CSS said `url('assets/…')` while the browser resolves that against the sheet, so three fonts 404ed at `/styles/assets/…` — the assert matched the string and stayed green. String asserts cannot see a resolution rule or a leak; the browser found both in one run, which is why the verification step is now the browser and not the string. From Vinicius's own eneba session: 132 files, 8.9 MB, one `missing` (the Cloudflare challenge script we ignore by D-012), 0 scripts, 0 off-origin requests, 0 console errors, page renders complete. | 
| **D-044** | 2026-09-05 | **E-24 rewritten, E-31 added** — every navigation target (`a`/`area` `href`, `form` `action`) is resolved against the page URL: captured pages point at our copy, everything else keeps the absolute original; a fragment stays a fragment and a `javascript:` href is dropped. A navigation to an uncaptured path answers 404 with a generated index of the bundle's own documents. | Vinicius clicked the hamburger menu in a rendered flat bundle and got `no such document in this bundle` on a black page. The old E-24 said a link is "left exactly as the origin wrote it", which is right for the 16 absolute links on that page and wrong for the **71 root-relative** ones: `/store/all` under our loopback origin is our own 404, not eneba's page. The rule confused *not rewriting* with *not resolving*. The same report also named what is not a bug: no button on the page does anything, because `flat` ships no script — that is the trade the emitter exists to make, and it is the reason nothing else on the page can break. |

# Decision log — PageProjection spec pack

Append-only. Clarifications and amendments relative to [engine-redesign.md](engine-redesign.md).  
To reverse a decision, append a new row; do not edit history.

| Date | Id | Topic | Decision |
|------|-----|-------|----------|
| 2026-08-12 | D-SPEC-0 | Meta | Spec pack created under `docs/page-projection/spec/`. Buildable contracts + impl specs are conceived from the redesign alone. Existing product code is not a design source. Code implementation is out of scope for this pack and requires a separate plan after `GAP.md` is empty. |
| 2026-08-12 | D-SPEC-1 | Document-level state wire | Redesign §5.2.6 requires publishing `<title>`, `lang`, `dir`, and viewport meta. §5.4 opcode table has no dedicated op (T6 `document` is deleted). **Adopt opcode `documentState = 12`** in the Dom plane: payload `{ title, lang, dir, viewportContent }`. Ordering: after `patch`, before live Cssom list/patch ops when mixed in a live frame; during establish, emit after `establishBegin` scroll restore data is known and before arming (client applies before arm). Never restores a node-tree `document` payload. |
| 2026-08-12 | D-SPEC-2 | Producer placement | Per redesign §4: accumulate, flush, and **binary encode** run **in-page** (Virtual). Node receives opaque frame parts, **rewrites URL strings**, applies to the mirror, relays `Body` to the API. API never parses the body (PP-WIRE-1). Node may decode only as needed for rewrite + mirror apply; it MUST NOT introduce JSON on this path (PP-WIRE-3). |
| 2026-08-12 | D-SPEC-3 | Pierce mechanism | Redesign mandates pierce of closed shadow and cross-origin iframes (§5.2.5). WP15 CDP snapshot identity remains a **spike, not default**. Default identity stays in-page WeakMap. Pierce adoption MAY use CDP **only** to discover closed roots / XO frames and inject host references into the in-page maps — never as a full-tree ferry or identity allocator unless WP15 is reopened with evidence. |
| 2026-08-12 | D-SPEC-4 | Checksum algorithm | `establishEnd.checksum` is an FNV-1a 32-bit over the ordered list of published element ids (ascending walk of anchored elements after the same chunked HTML parse the client uses), mixed with tag name UTF-8 bytes. Exact algorithm is normative in `contracts/05-establish.md` and `implementation/sidecar/establish.md`. |
| 2026-08-12 | D-SPEC-5 | VIEWPORT scroll sentinel | `scrollDirty` may key the viewport with sentinel id `0` (`NONE`). Wire uses opcode `scrollViewport` (no node id), not a `childList`/`patch` on id 0. |
| 2026-08-12 | D-SPEC-6 | In-page script packaging | §9 lists discrete `.ts` modules. The in-page producer is delivered as a single injected script built by concatenating fragments that mirror those modules’ algorithms (`identity`, `fmap`, `observe`, `frame`, `clock`, `encode`, `cssom`, `establish` walk). Each fragment ≤600 LOC; concat is a build step, not a second algorithm. |
| 2026-08-12 | D-SPEC-7 | Node rewrite of binary parts | After receiving an encoded part from the page, Node decodes ops, rewrites URL-bearing strings into `/w7s/virtual-*` forms, re-encodes the part for outbound relay **once**. This is the session rewrite hop (redesign §4 Node “rewrite”). It is not API re-parse. Intermediate JS object trees of the full document are forbidden; work is per-frame ops + string table only. |
| 2026-08-12 | D-SPEC-8 | Cssom id space | Cssom sheet/rule ids share the Dom `uint32` space (redesign §5.10). Allocation is a dedicated monotonic counter in the Cssom producer that never collides with Dom node ids: Dom allocates from identity space; Cssom allocates from a separate counter starting at `1` **within a generation**, and both spaces are disjoint by **construction** — Dom ids and Cssom ids MUST use non-overlapping ranges: Dom `[1 .. 0x7FFFFFFF]`, Cssom `[0x80000001 .. 0xFFFFFFFF]` with `0x80000000` reserved. Opcode disambiguates sheet vs rule. |
| 2026-08-12 | D-SPEC-9 | Soft vs hard navigation | Soft-nav: same Document, no generation bump, no re-establish. Hard-nav / top-level Document swap: bump generation, clear identity + mirror, run establish. Detection: document token and/or CDP non-same-document; never `framenavigated` alone (T3/D4). |
| 2026-08-12 | D-SPEC-10 | Resync watermark transport | Watermark `{ generation, coversThroughSequence }` is **not** inside the binary frame body. It rides as hub/gRPC **control metadata** alongside the resync frame parts (same response). Client applies parts with resync flag, then drains the live buffer using the watermark. Live `sequence` is not advanced by serving resync. |
| 2026-08-12 | D-SPEC-11 | Asset priority module | Prefetch scheduling is a first-class sidecar module `assetPriority.ts` (see `implementation/sidecar/assetPriority.md`). L2 does not reorder; priority is decided before fetch. |
